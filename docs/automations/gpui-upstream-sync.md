# Automation prompt — Sync MonoCode GPUI upstream

Source of truth for the **Sync MonoCode GPUI upstream** automation in MOLFAR (weekly, Wednesday 09:00,
`claude:opus`, effort high, worktree mode). After changing this file, paste everything below the line
into the automation's prompt. The `main` sync is a separate automation (`docs/automations/upstream-sync.md`).

Tooling it relies on: `scripts/upstream/apply.mjs [target-ref]` (per-path patch, exit codes 0/2/3/4),
`scripts/upstream/moves.mjs` (move map generate / `--check`), `.github/upstream-moves.json`,
`npm run native:check`.

---

You are running the weekly GPUI upstream sync for MOLFAR (`deluminor/molfar`), a standalone repository derived from MonoCode (`hardbeat920/monocode`). MonoCode is rewriting its app in Rust + GPUI on the branch `mc/migrate-monocode-to-gpui`. MOLFAR integrates that rewrite in **one long-lived draft PR**, #127. Your job: bring everything new from MonoCode's GPUI branch into that PR's branch as verified commits, so that the PR keeps growing with upstream while MOLFAR ports its own features on top.

## Branch model
- `upstream/mc/migrate-monocode-to-gpui` — MonoCode's GPUI branch (remote `upstream`, fetch only). Called **the GPUI ref** below. It is not mirrored on our repo.
- `upstream/main` — MonoCode's default branch. It belongs to the separate `main` sync. Never apply it here.
- `origin/migration/gpui-into-main` — MOLFAR's GPUI integration branch. It is the head of draft PR #127 into `main`. It is not protected, but only fast-forward pushes are allowed: never force-push it. A human also commits feature-parity work to it.
- `origin/main` — MOLFAR's product branch, protected, PR-only. You never push to it.
- `.github/upstream-sync.json` **on the GPUI branch**: `branch` is `mc/migrate-monocode-to-gpui`, and `syncedCommit` is the last GPUI-ref commit whose changes are in the GPUI branch. `main` has its own copy of this file that tracks `upstream/main`. The two are independent.
- MOLFAR shares **no commits** with MonoCode. Upstream changes arrive only as **patches** through `apply.mjs`, never as merges.
- The native app lives in `crates/monocode-core`, `crates/monocode-gpui`, `crates/mobile-link` and `vendor/gpui-pre*`, plus the bundle scripts `scripts/native-editor`, `scripts/native-settings`, `scripts/*native*.mjs`. The React/Tauri app stays the production app. Until parity group M01 (branding and isolation) lands, native crate names and app ids still use `monocode-*`. Do not rename those as part of a sync.

## Goal
1. Keep the GPUI branch current with `main`.
2. Apply the changes between `syncedCommit` and the GPUI ref to the GPUI branch as one sync commit, plus follow-up fix commits. The result must build, pass `check:web` and `native:check`, keep every MOLFAR feature, name and parity port, and bring in every upstream change.
3. Report each sync as a comment on PR #127, with English notes describing what changed.

The default outcome is new verified commits on `migration/gpui-into-main` and a notes comment on #127. A "Sync blocked" Issue is the exception, used only under the conditions in step 4c.

## Hard rules
1. Work only in this repository. Do not touch unrelated repos.
2. Never force-push. Never push to `main`. The only branch you push to is `migration/gpui-into-main`, and only as a fast-forward. Never push MonoCode refs to our repo.
3. Never `git merge`, `git cherry-pick`, `git rebase` onto, or otherwise bring MonoCode commits (anything reachable from the GPUI ref or `upstream/main`) into a MOLFAR branch, with or without `--allow-unrelated-histories`. It would add every MonoCode author back to MOLFAR's contributors, and CI rejects such branches. Upstream content arrives only through `node scripts/upstream/apply.mjs <GPUI ref>`. Merging `origin/main` into the GPUI branch is allowed: both are MOLFAR history.
4. Never push or open PRs to `hardbeat920/monocode`. `gh` commands must target `deluminor/molfar` (pass `-R deluminor/molfar`).
5. If there is nothing new to sync and `main` has nothing new for the branch, exit silently: no commit, no comment, no Issue.
6. Never commit conflict markers.
7. Never bypass git hooks: no `--no-verify`, no `-c core.hooksPath=...`, no hook-disabling env vars. If a hook fails, fix the cause.
8. Notes must be written by you after reading the actual diff, not dumped from `git log`. Language: English.
9. No authorship or tool attribution in commit messages, PR comments, PR bodies, Issue titles or bodies. Never append signatures, badges, links, or trailers such as `Made with Cursor`, `Generated by AI`, `Created by an agent`, `Co-authored-by: …`, or any equivalent mention that an agent, AI model, assistant, or tool authored the work. Technical descriptions of agent-session product features are allowed.
10. Never drop functionality from either side to make a conflict go away. Losing a MOLFAR feature, a parity port already on the branch, or an upstream change is a defect.
11. Never mark #127 ready for review, never merge it, and never edit the parity checklist sections of its body. Only the `Upstream sync` line of the body is yours (step 7).
12. Never import `.github/workflows/native-release.yml` or any other upstream workflow that publishes, signs, or uses secrets. Never import router port mapping (UPnP / NAT-PMP). See 4a.

## Steps

### 1. Preconditions
- Confirm `gh auth status` works.
- Ensure the `upstream` remote exists and points to MonoCode. Add it if missing:
  ```bash
  git remote get-url upstream || git remote add upstream https://github.com/hardbeat920/monocode.git
  ```
- Fetch:
  ```bash
  git fetch origin main migration/gpui-into-main
  git fetch upstream mc/migrate-monocode-to-gpui
  GPUI=upstream/mc/migrate-monocode-to-gpui
  ```
- If `origin/migration/gpui-into-main` does not exist, or PR #127 is not open (`gh pr view 127 -R deluminor/molfar --json state,headRefName`), stop. Report only the one-liner `GPUI integration PR is not open; sync skipped.`
- Work on a local branch `sync/gpui-YYYYMMDD` created from `origin/migration/gpui-into-main`. Do not dirty the user's WIP, and never work in the user's main checkout.
- Check the repository's git identity and state before any commit. `git config user.name` / `git config user.email` must be the owner's identity: never `CRLF Test`, and never an `@example.invalid` address. `git config --get core.bare` must be `false`. If any check fails, a test fixture corrupted the repository config. Stop and open a `Sync blocked: repository git config corrupted (YYYY-MM-DD)` Issue listing the bad keys. Do not repair the config yourself and do not commit.
- Check that `scripts/test/isolate-git-env.mjs` exists in the tree. If it is missing, stop before any push and report it. Without it, the pre-push tests can rewrite this repository's config.

### 2. Bring `main` into the branch
```bash
git rev-list --count HEAD..origin/main
```
- If the count is not `0`, run `git merge --no-edit origin/main`. This is MOLFAR history, so it is allowed.
- Conflict rules for this merge:
  - `.github/upstream-sync.json`: always keep **ours**, the GPUI branch's file (`branch: mc/migrate-monocode-to-gpui`, its `syncedCommit`). Taking `main`'s copy would make the next apply replay the wrong range.
  - `.github/upstream-moves.json`: keep both sides' entries (union per section). Then run `node scripts/upstream/moves.mjs --check`.
  - `CHANGELOG.md`: take `main`'s released sections and version links. Keep the branch's extra `Unreleased` entries merged into `main`'s `Unreleased` without duplicating sections.
  - Version numbers and lockfiles: take `main`'s versions. Regenerate lockfiles as in 4a. Never hand-edit them.
  - Everything else: combine both sides, as in 4b.
- Commit the merge with the default merge message. Do not push yet.

### 3. Divergence check
```bash
SYNCED=$(node -e 'console.log(require("./.github/upstream-sync.json").syncedCommit)')
git merge-base --is-ancestor "$SYNCED" "$GPUI"   # must succeed
git rev-list --count "$SYNCED".."$GPUI"
```
- If `syncedCommit` is not an ancestor of the GPUI ref, MonoCode rebased or force-pushed its GPUI branch. Do not guess a new base. Open `Sync blocked: MonoCode GPUI branch history rewritten (YYYY-MM-DD)` with:
  - `syncedCommit` and the new GPUI head;
  - their merge-base (`git merge-base "$SYNCED" "$GPUI"`) and the commit counts on each side;
  - a recommendation. If the rewritten commits are content-equal (compare with `git range-diff`), recommend setting `syncedCommit` to the matching new commit. Otherwise a human must choose the base.
  If step 2 produced a merge commit, still push it (step 7 push rules) so #127 stays current with `main`. Then stop.
- If the count is `0`: push the step-2 merge if there is one (step 7 push rules, no notes comment needed), report one line, and stop.
- Never use `HEAD..$GPUI` or `origin/main..$GPUI` for counting or notes. The histories are unrelated, so those ranges contain all of MonoCode.
- The GPUI ref sometimes merges `upstream/main`. Those commits may already be on our branch through `main`'s own sync (step 2). They show up as hunks that are already applied, or as conflicts whose two sides are identical. Keep one copy and record them as **Already in main** in the notes.

### 4. Apply the upstream patch
```bash
node scripts/upstream/apply.mjs "$GPUI"
```
It applies `git diff <syncedCommit> <GPUI ref>` to the working tree and index **one path at a time** as three-way patches. It updates `.github/upstream-sync.json` and prints JSON with these fields:
- `status`, `commits`, `conflicts`;
- `pending`: changes that were **not** applied, each with a diff under `.upstream-pending/<from>..<to>/`;
- `remapped`: paths translated through `scripts/upstream/rename-map.mjs` (Monos → Familiars);
- `retargeted`: edits applied to the MOLFAR path through `.github/upstream-moves.json`;
- `added`: new upstream files;
- `extracted`: paths from which MOLFAR moved declarations into other modules.

Exit codes:
- `0`: applied, or nothing to apply.
- `2`: conflict markers are left in the listed files.
- `3`: history diverged. Open the step-3 Issue and stop.
- `4`: pending ports were written. Conflicts may also be present; handle both.

After it runs, check that `.github/upstream-sync.json` still has `"branch": "mc/migrate-monocode-to-gpui"`.

"The range" means `<syncedCommit>..<GPUI ref>`, and "the upstream diff of a file" means `git diff <syncedCommit> <GPUI ref> -- <path>`. Before resolving anything, read `git log --oneline` of the range and the upstream diff of every conflicting or pending path.

MOLFAR's structure differs from MonoCode's in several ways:
- MOLFAR split large modules into folders.
- It renamed files to kebab-case (components stay `PascalCase.tsx`).
- It moved workspace state into a Zustand store (`src/app/workspace/store/`) and stateful flows (`src/app/workspace/flows/`).
- It regrouped Rust modules into domain folders.
- It renames the Monos concept to Familiars everywhere.

`.github/upstream-moves.json` records every move in four sections: `renames`, `splits`, `extractions` and `removed`. Read it before resolving anything.

#### 4a-bis. License notices — always port upstream changes (mandatory, also on a clean patch)
MIT and Apache-2.0 require every copy to carry the notices, so an upstream notice change is never dropped.
- Check what upstream changed in this range:
  ```bash
  git diff "$SYNCED" "$GPUI" --stat -- LICENSE 'LICENSE*' NOTICE 'NOTICE*' '**/LICENSE*' '**/NOTICE*' '**/COPYING*' '**/*.LICENSE*'
  git diff "$SYNCED" "$GPUI" -U0 | grep -E '^\+.*(Copyright|SPDX-License-Identifier|Licensed under)'
  ```
- `LICENSE`: keep MOLFAR's text. Add every new or changed upstream copyright line next to the existing `Copyright (c) 2026 Nick` line.
- `NOTICE`: keep MOLFAR's text and append upstream additions in substance. That covers new GPUI or Zed snapshot notices, vendored crates, bundled assets (icons, themes, editor bundles) and modifications notes. Never drop an upstream native notice.
- License files under `vendor/**`, `docs/native/LICENSE-*`, `crates/monocode-gpui/assets/**`: take them exactly as upstream has them.
- New **source** under a license other than MIT or Apache-2.0, or a new dependency under GPL, LGPL or AGPL: stop and open `Sync blocked: license review needed (YYYY-MM-DD)` listing the files and licenses. New MPL-2.0, Apache-2.0 or other permissive dependencies are allowed; name them under **Breaking / attention**.
- If `scripts/package-native-support.mjs` (`notices`) or `scripts/package-native.mjs` lists notice files, keep that list in sync with any notice files upstream adds.
- Record the result under **Breaking / attention**: `License notices: unchanged`, or the exact additions.

#### 4b. Product code — resolve by combining both sides
This covers `crates/`, `vendor/`, `scripts/`, `src/`, `src-tauri/src/` and `host/`, apart from the paths in 4a. Resolve a conflict when both sides' intent is clear and they can coexist:
- **Imports / `use` lists**: add only the missing symbols, at the sorted position. Never import a symbol twice.
- **Additive changes on the same line or list**: keep both.
- **MOLFAR renames vs upstream edits** (Mono → Familiar, `monocode.*` keys → `molfar.*`, camelCase → kebab-case files): apply the upstream logic using MOLFAR's names.
- **MOLFAR refactored or parity-ported a block that upstream changed**: keep MOLFAR's structure and port upstream's new behavior into it.
- **Upstream extracted code into a new module**: take the extraction. Make sure the old inline copy does not survive next to it.

After resolving, check every resolved file:
- `git diff "$GPUI" -- <path>` and `git diff origin/migration/gpui-into-main -- <path>`. Every upstream hunk must be present (possibly adapted), and no MOLFAR-only behavior may be lost.
- Grep for identifiers that upstream removed or moved in this range. None may remain as dead or duplicated code.

#### 4b-bis. Pending ports (mandatory whenever `pending` is non-empty)
- Read `.upstream-pending/<from>..<to>/manifest.json`. For each entry, read:
  - its `.diff`;
  - `git log --oneline <syncedCommit>..<GPUI ref> -- <path>`;
  - its move-map entry.
- Find where the code lives now (split `targets`/`notes`, `rg`, codegraph) and port the intent of every hunk in MOLFAR's form. Never recreate a removed file and never paste a monolith back.
- How to handle each reason:
  - `split`: port into the targets.
  - `removed`: port behavior changes into the replacement. Otherwise mark it **Not applicable**, with the reason.
  - `unmapped`: locate the code. For a 1:1 move, add a `renames` entry.
  - `moved-and-renamed-upstream`: keep MOLFAR's path and update the map entry.
  - `apply-failed`: apply it by hand.
- Ported code obeys the project checks (file size, layer boundaries, lint, clippy). Port matching upstream test changes into the MOLFAR test that covers the new location.
- Never commit `.upstream-pending/`. Every pending entry ends as **Ported** (with paths), **Not applicable** (with the reason) or **Needs human** (with what blocks it). A pending entry that needs a product decision does not block the sync: leave MOLFAR's code unchanged for it and list it under **Needs human**.

#### 4b-ter. New upstream files (`added`)
- React/TS files: rename to MOLFAR's convention (`kebab-case.ts`, components `PascalCase.tsx`, hooks `use-*.ts`), place them in MOLFAR's structure, and fix imports to MOLFAR paths and the `@/` alias. Record moves in `renames` and splits in `splits`.
- Native bundle scripts and Rust code that reference React sources by path (`import … from "../../src/…"`, `'./src/…'` inside esbuild `stdin`, `include_str!("…/src/…")`) must point at MOLFAR's paths. Check every such path resolves:
  ```bash
  grep -rnoE "(\.\./|\./)+src/[A-Za-z0-9_./-]+" scripts/native-editor scripts/native-settings scripts/*native*.mjs
  grep -rnoE 'include_(str|bytes)!\("[^"]+"' crates/monocode-core/src crates/monocode-gpui/src
  ```
- New Node `*.test.mjs` files that use `node:test` belong to `native:test:dev`, not vitest. Make sure the vitest `exclude` covers them, and add them to the `native:test:dev` script if upstream did not.
- New upstream files over 250 lines (`scripts/`, `src/`): split them like the surrounding MOLFAR code and record the split. The file-size ratchet does not apply to `crates/` and `vendor/`; leave Rust layout as upstream has it unless a MOLFAR port needs otherwise.
- Run `node scripts/upstream/moves.mjs --check` after committing (it reads the committed tree). It must pass.

#### 4c. When to stop with a blocked Issue instead
Stop only when at least one of these holds:
- Both sides changed the same behavior incompatibly, and keeping both needs a product decision.
- You cannot tell what one side intends.
- After a reasonable effort (step 5), `check:web` or `native:check` still fails in code touched by this sync.

Then:
- Discard the apply: `git reset --hard <the step-2 merge commit, or origin/migration/gpui-into-main if there was none> && git clean -fd`.
- If step 2 produced a merge commit, push it (step 7 push rules) so #127 stays current with `main`.
- Open an Issue titled `Sync blocked: MonoCode GPUI → #127 needs human (YYYY-MM-DD)`, labeled `sync-notes` if the label exists. The body starts with **Needs human**:
  - every conflicting path, with what each side did and the recommended resolution;
  - the blocking decision;
  - the range with both hashes;
  - the commands to reproduce:

    ```bash
    git fetch origin upstream
    git switch -c sync/gpui-YYYYMMDD origin/migration/gpui-into-main
    node scripts/upstream/apply.mjs upstream/mc/migrate-monocode-to-gpui
    ```

  Include the notes from step 6, with `Conflict status: Conflicts`.
- Post a short comment on #127 linking the Issue. Stop.

#### 4d. Branding and naming scan (mandatory, also on a clean patch)
```bash
git diff origin/migration/gpui-into-main -U0 | grep -E '^\+' | grep -v '^+++' | grep -iE 'monocode|usemono|\bmono\b'
```
Fix product identifiers and user-facing text:
- React app: `monocode.*` storage keys → `molfar.*`, `monocode:*` events → `molfar:*`, `MonoCode` UI text and component names → MOLFAR.
- Native user-facing text (window titles, menus, notifications, settings copy, error hints): MonoCode → MOLFAR wherever the branch already shows MOLFAR for the same surface. Check how the same string appears in `origin/migration/gpui-into-main`, and in the React source when a native test compares them (for example `hints_match_the_react_source`).
- Mono → Familiar renames that upstream code brought in unrenamed. The opposite also happens: check that the rename map did not change a fixed-size or wire value. Byte literals like `*b"…"` (Carbon FourCharCodes are exactly 4 bytes), protocol ids, persisted keys, and serialized enum tags must keep their length and meaning. Check with `cargo check`, and grep the added lines for `b"` literals.

Leave these alone:
- Native crate names, binary names, bundle ids (`monocode-core`, `monocode-gpui`, `dev.usemono.gpui`) and native data paths, until parity group M01 renames them. Do not do M01 inside a sync.
- Copyright lines, license texts and attribution notices.
- Upstream issue/PR links in comments.
- Code that intentionally handles legacy MonoCode data.
- `MonoCode #NNN` references in `CHANGELOG.md`.

Update tests that assert on renamed keys or names in the same way.

### 5. Verify
- `npm ci && npm run check:web` (vitest, `tsc --noEmit`, lint, file-size, layer-boundary and move-map checks). Stale `node_modules` cause false React test failures; `npm ci` first.
- If the range touched `scripts/native-editor/**` or `scripts/native-settings/**`, or the React modules they import (check the import lists from 4b-ter), rebuild the bundled assets and commit them:
  ```bash
  (cd scripts/native-editor && npm ci) && node scripts/native-editor/build.mjs
  node scripts/native-settings/build-arcade.mjs
  ```
- `npm run native:check`. It covers `native:test:dev`, `cargo fmt --check`, clippy with `-D warnings`, and core and gpui tests, and takes about 15–20 minutes. Run `cargo fmt --manifest-path crates/monocode-gpui/Cargo.toml --all` first when the rename map touched Rust files.
- If the range touched `src-tauri/` or the root `Cargo.*`: `cargo check --quiet` in `src-tauri/`. If it touched `host/`: `npm run test:host`.
- Sync-caused failures are yours to fix in follow-up commits on the sync branch: unresolved paths, renamed symbols, rename-map breakage, `rustfmt` after renames, lint or size ratchets, lockfiles. Re-run until green.
- A failure not caused by this sync (it also fails on `origin/migration/gpui-into-main` alone) does not block the push. List it with its output under **Breaking / attention**.

### 6. Analyze changes and write notes
Inspect at least:
- `git log --oneline "$SYNCED".."$GPUI"`
- `git diff --stat "$SYNCED" "$GPUI"`
- `git diff "$SYNCED" "$GPUI" -- CHANGELOG.md docs/native/` (upstream's own notes, which you verify against the code)
- Meaningful diffs: native UI and behavior, `monocode-core` contracts (sessions, providers, transcript, remote, mobile, store), React changes that ride along, settings defaults, data paths, build and packaging. Skip formatting-only and lockfile-only noise.

#### 6a. Notes format (the #127 comment)
```markdown
## GPUI sync <short syncedCommit>..<short new GPUI head> (YYYY-MM-DD)
### Summary
2–4 sentences: what this sync brings into the GPUI branch.
### Highlights
- Native: meaningful changes, related commits grouped.
- React/desktop: user-visible changes that ride along, if any.
### Parity impact
- Parity groups (M01–M22) this range touches, and whether MOLFAR ports on the branch were kept, adapted, or need follow-up. `None.` if not applicable.
### Breaking / attention
- Changes to MOLFAR-owned parts, skipped workflows, router-mapping hunks dropped, license notices, user-visible default changes (today vs after, and how to get the old behavior back), branding-scan renames, check results (pass, or failures with output). `None.` if empty.
### Upstream commits
- Subjects oldest → newest, max ~30; if more, show 30 and note the remainder.
### Conflict status
- `Clean patch`, or `Resolved` + every resolved path grouped as **Native** / **React & scripts** / **MOLFAR-owned**, one specific line each.
- **Main merge**: `none`, or the `origin/main` range merged in step 2 and its resolved paths.
- **Already in main**: upstream-main hunks that were already present.
- **Retargeted** / **Ported** / **Not applicable**: one line each.
### Needs human
- Only when something could not be ported or decided. Omit otherwise.
```
Be specific and honest. Prefer outcomes over hashes. Do not invent changes.

#### 6b. `CHANGELOG.md`
#127 ships with the next MOLFAR release after it merges, and `prepare.mjs` takes release notes only from `## [Unreleased]`. On the GPUI branch:
- React/desktop user-visible changes from this range go under `## [Unreleased]`, using Keep a Changelog sections. Merge them into existing entries; write `MonoCode #NNN` instead of bare `#NNN`; drop contributor handles and MonoCode version wording; use MOLFAR branding.
- Native-only changes (the GPUI app is an unreleased preview) do **not** go into `CHANGELOG.md`. They live in the #127 notes comments.
- Skip internal-only changes. Run `npx vitest run scripts/release/` after editing.

### 7. Commit, push, report
